# 圣诞粒子体验 · 发布包使用说明

这个文件夹里**只有编译后的成品网页**（`site/`），没有 `src/` 源码、没有工程配置、没有构建脚本。
别人拿到它只能看、只能玩，改不了你的实现。

- 成品网页：`site/`（HTML + 压缩后的 JS/CSS + 本地字体 + MediaPipe 模型，完全离线可用）
- 本机启动器：`start.bat`（同一 WiFi 下给手机 / 平板 / 其他电脑用）
- 公网临时链接：`share-public.bat`（生成一个 https 链接，任何设备任何网络都能打开）
- 证书工具：`make-cert.bat` / `make-cert.ps1`（手机要用摄像头就必须走 HTTPS）
- 防火墙修复：`fix-firewall.bat`（手机连不上局域网地址时运行一次，需管理员权限）
- 诊断面板：任意网址后加 `?diag=1`，看识别各环节是否正常
- 许可文件：`licenses/`（字体与依赖的开源许可，发布时请保留）

---

## 三种方式怎么选

| 方式 | 谁能用 | 摄像头 | 需要电脑开着 | 需要账号 |
|---|---|---|---|---|
| A. 同一 WiFi（`start.bat`） | 同一路由器下的设备 | 可以（HTTPS 地址） | 是 | 否 |
| B. 临时公网链接（`share-public.bat`） | 任何设备、任何网络 | 可以（真证书，无警告） | 是 | 否 |
| C. 永久托管（Cloudflare Pages 等） | 任何设备、任何网络 | 可以 | 否 | 是（免费） |

只想给家里人在手机上看 → 用 **A**。
想发链接给远方的朋友 → 用 **B**（临时）或 **C**（长期）。

## 方式 A：同一 WiFi 下使用（推荐先用这个）

1. 双击 `start.bat`。
   - 第一次会自动生成 HTTPS 证书，并弹出 Windows 防火墙询问，选 **允许访问**（专用网络）。
   - 会弹出一个黑色服务器窗口，**不要关**，里面印着地址。
2. 电脑自己打开：`http://localhost:8080`
3. 手机 / 平板（连同一个 WiFi）：

   ```
   https://192.168.3.61:8443
   ```

   （IP 以服务器窗口里显示的为准，换网络后会变）
4. 首次打开会有证书警告，这是一次性的，必须点过去，否则摄像头不会授权：
   - **iPhone / iPad**：显示详细信息 → 访问此网站
   - **Android Chrome**：高级 → 继续前往
   - **电脑 Edge/Chrome**：高级 → 继续访问
5. 允许摄像头权限，页面自动开始手势识别。

> 为什么手机必须用 `https://` 那个地址？
> 浏览器规定：只有 `https` 和 `localhost` 才允许调用摄像头。`http://192.168.x.x` 会被直接拒绝，
> 页面能开但手势不工作。这不是本项目的问题，是所有网页的通用规则。

关掉服务器窗口 = 网站下线。想换端口：`node serve.mjs --port 9000 --https-port 9443`。

### 手机连不上 `https://局域网IP:8443` 怎么办

先看服务器窗口还在不在、地址端口是不是 8443。窗口在、端口对，但手机还是打不开，几乎一定是
Windows 防火墙拦了 node：

1. 双击 `fix-firewall.bat`（会请求一次管理员权限，点“是”）。
   它会放行 TCP 8080 / 8443，并关掉系统里针对 `node.exe` 的**阻止入站**规则
   （Windows 里 Block 规则优先级高于 Allow，光“允许”没用，必须关掉 Block）。
2. 重新打开手机上的 `https://局域网IP:8443`。
3. 还是不行就查路由器：部分路由器开了“AP 隔离 / 访客网络隔离”，同 WiFi 设备互相看不到。
   换成手机热点连电脑，或者直接用方式 B。

### 手势没反应 / 只想确认它在干什么

在网址后面加 `?diag=1`，例如：

```
https://局域网IP:8443/?diag=1
```

> 这个面板只在网址带 `?diag=1` 时出现，平时打开是干净的圣诞树画面；面板右上角的 `×` 可以随手收起。

左上角会出现一块诊断面板，逐项显示：

| 字段 | 正常值 | 含义 |
|---|---|---|
| `mode` | `worker` 或 `main` | 识别跑在 Web Worker 还是主线程 |
| `delegate` | `GPU`（差机器 `CPU`） | MediaPipe 用 GPU 还是 CPU 推理 |
| `pump` | `rvfc`，手机上可能是 `interval` | 取帧方式，`interval` 是为了兼容隐藏视频不产帧的手机 |
| `frames` | 两个数字都在涨 | 已送识别 / 已回结果的帧数，不涨说明取帧卡住 |
| `hands` | 举手时开始上涨 | 检测到手部的帧数 |
| `fps` | 手机 10–30 | 识别帧率 |
| `error` | `-` | 有报错就看这里 |

`frames` 在涨但 `hands` 不涨 → 摄像头没对准手、光线太暗，或手离镜头太远（要能看清整只手）。
`frames` 不涨 → 浏览器没在解码视频帧，属于兼容问题，面板里的 `error` 和 `video` 字样请截图反馈。

## 方式 B：生成一个临时公网链接（不需要账号）

1. 双击 `share-public.bat`。
2. 第一次会自动下载 `cloudflared`（约 55 MB，只需一次）。
3. 窗口里会出现一行：

   ```
   https://something-random.trycloudflare.com
   ```

4. 把这个链接发给任何人，手机、平板、异地电脑都能打开，**摄像头正常**（真证书，无警告）。
5. 关掉窗口链接就失效；下次运行会换一个新网址。

适合：临时给朋友看、异地演示。不适合长期挂着。

> 如果下载失败或链接打不开：说明当前网络连不上 Cloudflare，改用方式 A 或方式 C。

## 方式 C：永久托管（只上传 `site` 文件夹）

任何静态托管都能用，**只上传 `site/` 里的内容**即可（不要上传整包、不要上传 `src/`）。

### Cloudflare Pages（免费、国内可访问性较好）
1. 打开 <https://dash.cloudflare.com/> → Workers & Pages → Create → Pages → Upload assets
2. 把 `site` 文件夹整个拖进去 → Deploy
3. 得到 `https://项目名.pages.dev`，手机直接打开，摄像头正常

### Netlify（最简单）
1. 打开 <https://app.netlify.com/drop>
2. 把 `site` 文件夹拖进页面
3. 立刻得到 `https://随机名.netlify.app`

### Vercel
1. <https://vercel.com/new> → 选择 "Deploy" 的静态上传方式，或 `npx vercel site --prod`

### GitHub Pages（项目子路径也可以）
1. 新建仓库，把 `site/` 里的内容推到 `main` 分支根目录
2. Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`
3. 地址是 `https://用户名.github.io/仓库名/`
   本包已按相对路径构建，放在子路径下也能正常加载模型和字体。

> 托管后地址是 https，摄像头权限正常，不需要任何证书警告。
> 这一步不涉及源码：平台只会收到 `site/` 里压缩后的产物。

## 常见问题

**页面能打开，但没有手势 / 一直提示摄像头？**
99% 是地址不是 HTTPS。确认用的是 `https://...`，并且点过了证书警告。

**手机打不开局域网地址？**
- 确认手机和电脑在同一个 WiFi（不是访客网络，很多路由器的访客网络隔离设备）。
- Windows 防火墙第一次弹窗要选"允许"，否则外部设备连不上。
- 电脑 IP 变了：看服务器窗口里的新地址，或重新运行 `make-cert.bat` 生成新证书。

**画面卡 / 掉帧？**
手势推理默认 30Hz，低端手机可以只用键盘：`1` `2` `3` `O` `F` / `R` `空格` `T`。
详见页面右侧操作提示。

**字体、模型要联网吗？**
不要。`site/` 里已包含 Noto Sans SC / Great Vibes 字体、MediaPipe WASM 和手部模型，纯离线。

**把整个文件夹拷给别人行不行？**
行，但对方需要装 Node.js 22 才能跑 `start.bat`。真正常见的做法是方式 B / C：给对方一个链接，
你这边什么都不用发。若要发压缩包，`Christmas-Experience-Web.zip` 就是可移交的版本（不含 `src/`）。
